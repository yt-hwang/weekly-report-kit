# 첫 설정 인터뷰 — 기본 정보 모으기

**질문 방식:** 질문 도구(Claude Code 의 AskUserQuestion, claude.ai 의 선택지 버튼)가 있으면 반드시 그걸로 묻는다 — 한 번에 최대 4문항, 문항당 선택지 2~4개, '기타'는 자동으로 붙는다. 도구가 없으면 번호 객관식으로 한 메시지에 묶어 묻는다. 이미 아는 것(설정 파일·첨부·앞 대화)은 다시 묻지 않는다.

## 1라운드 — 기본 (4문항)
| 질문 | 선택지 예 |
|---|---|
| 무엇을 파나요? | 앱·SaaS 구독 / 온라인 클래스·강의 / 쇼핑몰 / 오프라인 매장·예약 |
| 돈이 들어오는 순간(퍼널 끝)은? | 유료 결제 / 첫 구매 / 예약 확정·방문 / 상담 신청 |
| 한 주는 언제부터? | 월 시작 / 수 시작 / 일 시작 (시간대는 '기타' 또는 사업 위치로 추정 후 4라운드에서 확인) |
| 보고서는 누가 보나요? | 나 혼자 / 팀 주간 회의 / 투자자·파트너 |

사업 이름·시간대·서비스 주소는 자유 입력으로 한 줄 받는다("사업 이름과 홈페이지 주소(또는 메인 화면 스크린샷)를 알려 주세요").

## 2라운드 — 쓰는 서비스 (4문항, 모두 다중 선택)
| 질문 | 선택지 |
|---|---|
| 방문은 어디서 보나요? | GA4 / 네이버 애널리틱스 / 사이트 빌더 기본 통계(Wix·Squarespace·아임웹·카페24) / 아직 없음 |
| 광고는? | 메타(인스타·페북) / 구글 / 틱톡 / 네이버·카카오 |
| SNS·콘텐츠는? | 인스타그램 / 틱톡 / 유튜브 / 블로그·카톡 채널 |
| 가입·주문·결제 기록은? | 자체 DB / 구글 폼·시트 / 결제 도구(Stripe·토스·Square) / 쇼핑몰 관리자(스마트스토어·Shopify) |

## 3라운드 — 고른 서비스만, 서비스별 필요한 것
고른 것만 묻는다(4문항씩 끊어서). 각 서비스에서 매주 받을 방법은 셋 중 하나: **연결**(API·MCP·CLI 가 이 환경에 있을 때) / **내보내기 파일**(CSV·엑셀) / **스크린샷**. 처음 쓰는 사람에겐 스크린샷을 기본 추천.

| 서비스 | 꼭 확인할 것 | 매주 받을 것 |
|---|---|---|
| GA4 | 가입·구매가 이벤트로 잡히나(이벤트 이름: sign_up·purchase 등) · 전환(주요 이벤트) 설정 여부 | 보고서 > 참여도 > 이벤트, 획득 > 트래픽 획득(세션 소스/매체), 일별 사용자 — 기간 맞춰 캡처 |
| 네이버 애널리틱스 | 사이트 등록·전환 스크립트 여부 | 방문 분석·유입 경로 엑셀 |
| 사이트 빌더 통계 | 방문(visits)인지 방문자(visitors)인지 | 트래픽 화면 캡처 |
| 메타 광고 | 픽셀 있나 · 결과(전환)로 무엇을 최적화하나 | 광고 관리자 캠페인 표 — 지출·노출·도달·결과·결과당 비용 열 |
| 구글 Ads | 전환 액션 이름 | 캠페인 표 — 비용·클릭·노출·전환 |
| 틱톡 광고 | 픽셀 이벤트 | 캠페인 표 — 비용·노출·전환 |
| 네이버 검색광고 / 카카오모먼트 | 전환 추적 설치 여부 | 보고서 엑셀 또는 캡처 |
| 인스타그램 | **프로페셔널(비즈니스·크리에이터) 계정인가** — 아니면 인사이트가 없다 | 게시물별 인사이트(조회·좋아요·저장·공유·팔로우), 프로필 방문·링크 클릭 |
| 틱톡 | 비즈니스·크리에이터 계정 | 분석 > 콘텐츠 조회 |
| 유튜브 | 쇼츠·롱폼 | 스튜디오 > 분석 > 콘텐츠 |
| 블로그·카톡 채널 | 숫자를 볼 수 있나(없으면 '…'로 표시) | 통계 화면 캡처 |
| 자체 DB | 가입 시 유입(UTM·referrer) 저장 여부 | 이번 주 단계별 건수 + 유입별 건수(쿼리 또는 캡처) |
| 구글 폼·시트 | '유입' 칸이 있나(없으면 추가 권장) | 시트 캡처·CSV |
| 결제 도구 | 환불 제외 여부 · **첫 결제만 셀지 갱신 포함인지** | 결제 완료 건수·금액(신규 구독/갱신 구분) |

'꼭 확인할 것'이 '아니오'면 막지 말고 진행한다 — 그 칸은 비우고, `next`(다음 할 일)에 "○○ 설정하기"를 넣는다(예: 인스타 프로페셔널 계정 전환, 링크에 UTM).

## 4라운드 — 확인 한 번(색 + 퍼널)
색과 퍼널 제안을 한 메시지로 확인받는다: "버튼 색 #xxxxxx(홈페이지 '시작하기' 버튼)로 맞추고, 퍼널은 방문자(GA4) → 가입(DB) → 첫 결제(Stripe)로 갈게요 — 괜찮을까요?"

### 색 뽑는 법
- **링크를 받으면:** 페이지를 직접 열어 본다. 글만 가져오는 웹 도구(WebFetch 등)는 스타일이 사라져 색이 안 나온다 → `curl` 로 원본 HTML 과 연결된 CSS 를 받거나 브라우저 도구로 연다. 둘 다 안 되면 추측하지 말고 메인 화면 스크린샷을 요청. 우선순위: ① 주요 버튼(CTA) 배경색 ② 로고 색 ③ `<meta name="theme-color">` ④ CSS 변수(`--primary`, `--brand` 등). 흰색·검정·회색은 제외.
- **스크린샷을 받으면:** 이미지에서 가장 눈에 띄는 버튼·로고 색을 읽는다.
- 고른 색을 `brandColor` 에 넣는다(대시보드가 연한 톤·막대·다크 모드를 이 색에서 만든다). 너무 밝아 흰 글자가 안 읽히는 색(노랑·연두 등)이면 한 단계 진하게.
- 브랜드가 주황·빨강 계열이면 퍼널의 '멈춘 사람' 색과 겹치므로 `dropColor: '#8a8f8c'`.
- 사용자에게 "홈페이지 버튼 색 #xxxxxx 로 맞췄어요"처럼 근거와 함께 한 줄로 알려 준다.
- 링크도 스크린샷도 없으면 기본 초록 그대로.

## 끝나면
