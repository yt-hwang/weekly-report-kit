# 채널별로 숫자 가져오는 법

원칙: API 가 있으면 API, 없으면 CSV 내보내기, 그것도 어려우면 **화면 캡처**(Claude 가 읽어서 옮김). 기간은 항상 설정의 한 주(시작 요일·시간대)로 맞춘다.

## 분석
| 도구 | 퍼널에 쓰는 숫자 | 가져오는 곳 |
|---|---|---|
| GA4 | 방문자(활성 사용자)·세션, 이벤트 수(클릭·가입), 일별 사용자, 소스/매체 | 보고서 > 참여도 > 이벤트, 획득 > 트래픽 획득(세션 소스/매체). API: GA4 Data API(서비스 계정) |
| 네이버 애널리틱스 | 방문 수·순방문자, 유입 검색어, 일별 | 방문 분석 > 방문 수 / 유입 분석 > 유입 경로 — 엑셀 다운로드 |
| Plausible·Umami | 방문자, 목표(goal) 전환 | 대시보드 CSV 내보내기 또는 Stats API |
| 없음 | 방문 단계를 빼고 "신청 페이지 조회" 같은 가장 앞 단계부터 시작 | — |

## 광고
| 플랫폼 | 타일 3개 추천 | 가져오는 곳 |
|---|---|---|
| 메타(인스타·페북) | 지출 · 노출(도달) · 전환(결과) + 전환당 비용 | 광고 관리자 > 캠페인 표(열에 '웹사이트 등록 완료' 추가) 캡처 또는 내보내기 |
| 구글 Ads | 지출 · 클릭 · 전환 | 캠페인 > 보고서 다운로드 |
| 네이버 검색광고 | 지출 · 노출/클릭 · 전환 | 보고서 > 다차원 보고서(키워드별) 엑셀 |
| 카카오모먼트 | 지출 · 노출/클릭 · 전환 | 보고서 > 캠페인 보고서 다운로드 |
| 틱톡 광고 | 지출 · 노출 · 전환 | Ads Manager > 캠페인 > 내보내기 |

광고 관리자의 '전환'은 광고를 본 뒤 나중에 가입한 사람까지 세서 실제 가입(자체 DB)보다 크게 나오기 쉽다. 퍼널엔 DB, 광고 섹션엔 플랫폼 숫자, 차이는 note 에.

## SNS 콘텐츠 (content 표)
| 채널 | 열 추천 | 가져오는 곳 |
|---|---|---|
| 인스타그램 | 조회 · 좋아요 · 저장 · 공유 · 팔로우 | 게시물 > 인사이트 보기 캡처 / 프로페셔널 대시보드 |
| 틱톡 | 조회 · 좋아요 · 공유 | 크리에이터 도구 > 분석 > 콘텐츠 |
| 유튜브(쇼츠) | 조회 · 시청 시간 · 구독 | YouTube 스튜디오 > 분석 > 콘텐츠 |
| 네이버 블로그 | 조회 · 공감 · 댓글 | 내 블로그 통계 > 게시물 조회수 순위 |
| 스레드 | 조회 · 좋아요 · 답글 | 인사이트 |

같은 콘텐츠를 여러 채널에 올리면 행 = 콘텐츠, 열 = 채널(예: ['콘텐츠','인스타','틱톡']).

## 가입·주문 (퍼널 뒤쪽 · 유입 경로)
| 데이터 | 세는 법 |
|---|---|
| 자체 DB | 이번 주 생성된 계정/주문 수, 가입 시 저장한 유입 기록(utm_source 또는 referrer)로 경로별 집계 |
| 스마트스토어 | 판매 관리 > 주문 통합검색(기간) 엑셀, 유입은 비즈어드바이저 > 마케팅 분석 |
| Shopify | Analytics > Reports > Sessions by referrer / Orders |
| Stripe·토스페이먼츠 | 결제 완료 건수·금액(환불 제외) |
| 스프레드시트·폼 | 응답 시각으로 기간 필터 |

유입 기록이 없다면 이번 주부터 모든 광고·프로필 링크에 UTM 을 붙이도록 next 에 넣는다(`?utm_source=instagram&utm_medium=social&utm_campaign=<콘텐츠명>`).
